## Published preview

The quickstarts target published **0.0.1-rc.7**, a prerelease rather than stable
0.0.1. Native iOS uses Swift Package Manager; Android uses Maven Central; React
Native/Expo uses `@crumbsdk/react-native@0.0.1-rc.7` with Nitro `0.37.1`.

rc.7 redacts more before a report is stored, delivers each report only to the
project it was created for, fixes React Native Android release builds minified
with R8, and makes the Maven artifacts Kotlin 2.0 compatible. Support floors are
unchanged. Read the [rc.7 release and migration notes](https://github.com/alexander126/crumb/blob/main/docs/releases/0.0.1-rc.7.md)
before upgrading: reports queued before the upgrade are not uploaded
automatically, an app must not roll back to rc.6 once rc.7 has queued a report,
and native Android code that called the removed JavaScript crash methods
directly must move to `crumb-react-native`. The
[rc.6](https://github.com/alexander126/crumb/blob/main/docs/releases/0.0.1-rc.6.md)
and [rc.5](https://github.com/alexander126/crumb/blob/main/docs/releases/0.0.1-rc.5.md)
notes remain available for earlier upgrades.

Native iOS rc.7 is not a public CocoaPods release. The rc.3 CocoaPods setup is a
separate legacy path. React Native rc.7 instead bundles its iOS dependencies and
requires the Expo plugin or bare-app Podfile helper in the quickstart.

The standalone source-map CLI is published at rc.7. The React Native package
already includes its compatible, pinned rc.4 uploader; most apps do not need a
second Crumb package. npm prereleases use `next`; use exact quickstart versions.

The [published rc.7 release](https://github.com/alexander126/crumb/releases/tag/0.0.1-rc.7),
[React Native npm package](https://www.npmjs.com/package/@crumbsdk/react-native/v/0.0.1-rc.7)
and [source-map CLI](https://www.npmjs.com/package/@crumbsdk/source-maps/v/0.0.1-rc.7)
are the distribution references. A future main-branch version string does not
establish publication.

## Using optional features

Guides describe the published rc.7 preview SDK and the configuration each feature
needs. Finish the first-report quickstart before adding optional collection.
Publication does not establish compatibility with every host app, device or
update pipeline. Verify your own release builds and preserve explicit raw stacks
when source maps are missing or do not match.

The dashboard and SDK need compatible report formats: baseline reports use 1.0; the iOS native-frame extension and rendering use 1.1 (Android managed stacks without rendering remain 1.0); screen context uses 1.2. Coordinate a compatible Crumb service before distributing preview-enabled builds. Older reports do not gain missing evidence retroactively.

## Support floors

- Native iOS: iOS 15 or newer.
- Native Android: API 26 or newer, Java 17 bytecode.
- React Native: 0.79 or newer, iOS 15.1 or newer, Android API 26 or newer.
- Expo: a native development or production build; Expo Go is unsupported.
- Guided setup and source-map build commands: Node.js 22 or newer.

Keep higher deployment targets required by your host app and its framework. These are minimums, not instructions to downgrade a current application.
