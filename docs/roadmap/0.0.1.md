# Crumb 0.0.1 roadmap

`0.0.1` is the first usable native iOS and Android vertical slice. A report
must move safely from explicit user invocation to a durable queue, ingestion,
and a small web inbox. React Native follows the native release and is not a
`0.0.1` gate.

## Release tasks

- [x] **T01 — Native report envelope**
  - Build and serialize schema-valid envelopes on iOS and Android.
  - Keep report IDs, clocks, and runtime facts injectable for deterministic tests.
  - Prove equivalent mappings for release, diagnostics, logs, stacks, privacy,
    and artifacts.
  - Gate: contract, Swift, and Kotlin tests pass from a clean checkout.

- [x] **T02 — Reporter lifecycle and invocation**
  - Make configured programmatic and foreground-shake invocation real SDK
    behavior rather than demo-owned behavior.
  - Open the form immediately while diagnostics finish independently.
  - Handle duplicate presentation, interactive dismissal, rotation,
    backgrounding, and host destruction.
  - Gate: lifecycle UI flows pass on both platforms.

- [x] **T03 — Screenshot artifact pipeline and masking**
  - Add removal/preview, dimension and byte limits, encoding, SHA-256, and the
    artifact manifest consumed by T01.
  - Add custom masking interfaces and document the UIKit, SwiftUI, Android
    Views, Compose, and WebView support boundary.
  - Gate: no unmasked configured field reaches the encoded artifact.

- [x] **T04 — Durable local report queue**
  - Atomically store sanitized envelope and artifacts in app-private storage.
  - Survive restart, enforce storage limits, and model pending/uploading/failed
    states without losing the user's report.
  - Gate: forced termination and restart integration tests retain the report.

- [x] **T05 — Ingestion and artifact storage**
  - Implement the TypeScript modular monolith, PostgreSQL metadata, and
    S3-compatible artifact storage.
  - Implement write-only project authentication and init/complete/cancel with
    idempotency, size, and digest verification.
  - Gate: a native fixture is accepted once and isolated to its project.

- [x] **T06 — Reliable native uploader**
  - Upload queued reports and signed artifacts with retry, backoff,
    cancellation, and offline recovery.
  - A failed infrastructure check must never prevent local submission.
  - Gate: airplane-mode submission uploads exactly once after reconnection.

- [x] **T07 — Primitive report inbox**
  - Add authenticated project selection, report list, and evidence detail.
  - Keep AI, clustering, assignment, and integrations outside this release.
  - Gate: an uploaded report and sanitized artifact are inspectable end to end.

- [x] **T08 — Crumb infrastructure health**
  - Add the Crumb-owned health endpoint and record device connectivity and API
    reachability independently.
  - Gate: unavailable API context is reported without blocking the reporter.

- [x] **T09 — Native distribution preparation**
  - Validate remote Swift Package installation and a corrected CocoaPods spec.
  - Stage Android AARs with Maven coordinates, sources, and consumer rules.
  - Centralize the SDK version and replace package metadata placeholders.
  - Gate: clean consumer apps install only staged or immutable artifacts;
    public registry publication remains part of T11.

- [x] **T10 — Quality, privacy, performance, and security**
  - Cover supported OS versions, accessibility, appearance, localization,
    malformed inputs, redaction, queue limits, and Sentry/Crashlytics coexistence.
  - Measure startup, report latency, memory, binary, and network overhead.
  - Gate: documented budgets and privacy guarantees pass on real devices.

- [x] **T11 — Hosted control plane foundation**
  - Deploy the portable monolith, PostgreSQL, and private object storage into
    an isolated Railway staging environment.
  - Verify Firebase identities while keeping organizations, memberships,
    projects, roles, invitations, and SDK credential lifecycle in PostgreSQL.
  - Add one-time SDK key creation, revocation-ready storage, and an audit trail.
  - Gate: a verified staging user can create a workspace and ingest a report
    without any cross-organization access or plaintext credential persistence.
  - Evidence is retained with the deployment in the private `crumb-cloud`
    repository.

- [x] **T12 — Cloud boundary and dashboard foundation**
  - Extract the hosted API into a private cloud-product repository while the
    native SDKs and versioned report-envelope contract remain independently
    distributable.
  - Preserve the verified Railway staging environment and its Firebase,
    PostgreSQL, and private object-storage boundaries during the move.
  - Turn the reviewed brand, dashboard, authentication, onboarding, and state
    references into implementation-ready routes, tokens, and acceptance cases.
  - Scaffold the React, Vite, TypeScript, and shadcn web application beside the
    cloud API without introducing unsupported product capabilities.
  - Gate: staging ingestion and control-plane acceptance still pass from the
    cloud repository, and the responsive web shell matches the approved system.

- [x] **T13 — Authenticated web workflow**
  - Implement Firebase Google and email/password sign-in, workspace and project
    onboarding, one-time SDK-key reveal, and first-report guidance.
  - Replace the primitive access-key surface with authenticated report inbox and
    report-detail APIs scoped to the user's organization and project access.
  - Add the supported team, key-management, audit, and customer service-health
    flows together with loading, empty, partial, stale, and failure states.
  - Keep AI issue grouping, release intelligence, integrations, and the internal
    operations console outside the release until their backend contracts exist.
  - Gate: a nontechnical tester can sign in, configure a project, submit from a
    device, and inspect the report and service health end to end.

- [ ] **T14 — Release candidate and 0.0.1**
  - Add CI, changelog, license/privacy documentation, dogfood hosts, release
    artifacts, and checksums.
  - Confirm the product name before irreversible public package publication.
  - Gate: the latest `0.0.1` release candidate passes dogfooding before the
    final `0.0.1` tag.

## After 0.0.1 — React Native

- [x] Build the thin autolinked adapter over the released native SDKs.
- [x] Add native reporter invocation, OTA bundle identity, a bounded JavaScript log
  provider, optional console capture, and error-time JavaScript stacks.
- [x] Mirror JavaScript logs into native memory when they are written so a
  blocked JavaScript thread never delays or prevents the native report.
- [x] Add explicitly opt-in JavaScript exception and unhandled-rejection
  capture with bounded sanitized recovery, deduplication, and offline queueing.
