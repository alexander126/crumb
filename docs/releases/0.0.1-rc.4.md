# Crumb 0.0.1-rc.4 candidate

This is a prerelease for the private pilot, not stable 0.0.1. Source preparation
is not proof of registry availability. Keep using the published rc.3 quickstarts
until the exact rc.4 artifacts are confirmed available.

## One release identity

| Distribution | Candidate identity |
| --- | --- |
| Native iOS, Swift Package Manager | Git tag `0.0.1-rc.4`; products CrumbCore and CrumbUI |
| Android, Maven Central | `com.crumbsdk:crumb-core:0.0.1-rc.4` and `com.crumbsdk:crumb-ui:0.0.1-rc.4` |
| React Native / Expo, npm | `@crumbsdk/react-native@0.0.1-rc.4`, channel `next` |
| Source-map CLI, npm | `@crumbsdk/source-maps@0.0.1-rc.4`, channel `next` |

The native `0.0.1-rc.4` and adapter `react-native-v0.0.1-rc.4` tags must point to
one independently reviewed, merged commit. The source-map CLI uses the native
tag. Never publish from a moving branch or replace an existing tag/version.
The root VERSION drives both native constants, both npm package versions,
React Native's native dependency pin and the CLI lockfile.

## Changes to evaluate

The candidate adds opt-in JavaScript crash recovery, failure-time diagnostics,
native platform stacks, optional recent rendering measurements, logical screen
context, SDK configuration/privacy precedence and the source-map upload CLI.
Android recovery now schedules upload without another foreground transition.
See the [changelog](../../CHANGELOG.md).

JavaScript crash capture remains disabled by default. It does not provide
arbitrary native crash interception, session replay, analytics or automatic
freeze monitoring. Screen context contains static labels/templates, not route
parameter values or navigation history. Rendering remains separately opt-in;
missing GPU or diagnostic observations must not be presented as measurements.

A compatible report consumer is required before enabling new evidence:
base reports use 1.0, iOS native stacks/rendering use 1.1, and screen context
uses 1.2. Existing reports do not gain new evidence retroactively.

## iOS installation migration

### Native Swift

Use Swift Package Manager, selecting the exact `0.0.1-rc.4` tag after publication.
Link both **CrumbCore** and **CrumbUI**. Remove the old Crumb CocoaPods products
before linking their SPM replacements to avoid duplicate modules. Native iOS
requires iOS 15 or newer and Swift 6; preserve higher app requirements.

CocoaPods remains a local build tool for React Native's bundled dependencies.
This release does not require a new CocoaPods trunk version. Existing rc.3 pod
publications remain the legacy installation path; do not assume rc.4 exists in
trunk or point a published rc.3 pod at unreleased code.

### Expo

After npm publication, install exact `@crumbsdk/react-native@0.0.1-rc.4` and
`react-native-nitro-modules@0.37.1`. Add `"@crumbsdk/react-native"` to the existing
Expo plugins list, retaining `expo-build-properties` and existing plugins.
Keep iOS deploymentTarget at least 15.1 and Android minSdkVersion at least 26.
Remove old Crumb local-pod plugins/manual Crumb declarations before prebuilding.
Run a new native prebuild and development or production build. Expo Go cannot
load this native SDK; rebuilding JavaScript alone is insufficient.

### Bare React Native

Install the same exact npm packages. Inside each app target, before
`use_react_native!`, add:

```ruby
require File.join(File.dirname(`node --print "require.resolve('@crumbsdk/react-native/package.json')"`.strip), 'scripts', 'ios')
crumb_native_pods!
```

Remove manual CrumbSDK, CrumbSDKCore and CrumbSDKUI declarations first, then run
`npx pod-install` and rebuild. If the lockfile reports old Crumb pod sources, run
`bundle exec pod update CrumbSDKCore CrumbSDKUI PLCrashReporter --no-repo-update`
(or `pod update` without Bundler). Review the lockfile; do not delete it or update
unrelated pods. Resolve incompatible PLCrashReporter pins rather than shipping
two copies. RN requires 0.79 or newer; retain higher framework floors.

## Source-map CLI

After publication, install `@crumbsdk/source-maps@0.0.1-rc.4` as a development
dependency. It requires Node.js 22 or newer. Save the final Hermes bundle and
composed map from each actual build, with a unique immutable bundleVersion.
Use a dedicated project-scoped source-map upload credential, never the SDK key.
See the [CLI guide](../source-maps.md). Dry-run validates locally; it does not
prove authenticated upload or hosted symbolication.

## Publication sequence after review

1. Merge the green release PR through independent review. Record its exact SHA.
2. Create the native and React Native release tags on that same SHA. The native
   tag starts the existing GitHub release workflow. Wait for verified native
   archives, manifest and SHA256SUMS; inspect their git_revision.
3. Run **Publish native registries** with tag `0.0.1-rc.4`, registry **maven**,
   confirmation `publish 0.0.1-rc.4`. CocoaPods trunk is not a release prerequisite.
4. Wait for Maven propagation, then run **Publish React Native SDK to npm** with
   tag `react-native-v0.0.1-rc.4`, channel `next`, confirmation
   `publish @crumbsdk/react-native@0.0.1-rc.4`.
5. Run **Publish source-map CLI to npm** with tag `0.0.1-rc.4`, channel `next`,
   confirmation `publish @crumbsdk/source-maps@0.0.1-rc.4`.
6. Verify the published npm versions/integrity and Maven coordinates, then build
   fresh SPM, Maven, bare RN and Expo consumers from those exact distributions.
7. Promote the public release availability table, notices and three quickstarts
   only after registry availability and their installation instructions pass.
   Preserve explicit rc.3 migration instructions for existing users.

Use existing trusted publication configuration. If registry credentials,
permissions or trusted-publisher setup are missing, stop with that concrete
blocker; never add a token to the repository or use a different package name.

## Gates still required before accepting the pilot

- CI and packaging checks on the exact merged candidate commit.
- Matching artifact checksums, release manifest revision and package versions.
- Fresh SPM, Maven, bare RN and Expo installs; local source linking is not a pass.
- Synthetic authenticated report submission and offline retry from each path.
- On-device privacy precedence, masked screenshot/log/network evidence and SDK
  customization; include available physical-device coverage.
- Fatal JS and nonfatal rejection recovery on iOS/Android Release builds, once
  only, with the original screen and diagnostics retained.
- Dashboard evidence and readable stacks using matching maps; explicit raw-stack
  fallback for missing and incorrect maps, without hiding the captured cause.
- No unresolved critical/high-severity pilot defect.

Keep raw reports, maps, credentials, device files and hosted evidence private.
No stable 0.0.1 release, marketing launch or production promotion is implied by
preparing or publishing this candidate.
