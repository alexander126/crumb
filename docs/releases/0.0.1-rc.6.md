# Crumb 0.0.1-rc.6 candidate

This prerelease corrects the bundled React Native iOS dependency wrapper and
isolates native capture tests. It includes the [rc.5 setup and source-map
features](0.0.1-rc.5.md) without changing runtime APIs, privacy behavior or
supported platforms. Source preparation does not establish registry availability
or complete pilot acceptance. Stable 0.0.1 remains a separate release.

## Exact distributions

| Distribution | Candidate identity |
| --- | --- |
| Native iOS, Swift Package Manager | Tag `0.0.1-rc.6`, products CrumbCore and CrumbUI |
| Android, Maven Central | `com.crumbsdk:crumb-core:0.0.1-rc.6` and `com.crumbsdk:crumb-ui:0.0.1-rc.6` |
| React Native / Expo | `@crumbsdk/react-native@0.0.1-rc.6`, npm channel `next` |
| Standalone source-map CLI | `@crumbsdk/source-maps@0.0.1-rc.6`, npm channel `next` |

Native tag `0.0.1-rc.6` and adapter tag `react-native-v0.0.1-rc.6` must identify
the same independently reviewed merge commit. VERSION synchronizes the native
SDK constants, both npm package versions, the adapter native pin and CLI lockfile.
Existing tags and registry versions must never be replaced.

The adapter continues to depend on the exact compatible
`@crumbsdk/source-maps@0.0.1-rc.4`. Its uploader API is unchanged; it is installed
automatically and stays out of the app's runtime bundle. The independently
installable CLI is versioned rc.6 with the other distributions. Users do not need
to install a second Crumb package or align its version manually.

## Corrections and migration

The npm archive's local PLCrashReporter pod wrapper now declares iOS 15.0,
matching the existing native Crumb minimum. The adapter still requires iOS 15.1
or newer. The official PLCrashReporter 1.12.0 binary, download URL, archive
SHA-256, license and privacy manifest are unchanged. This wrapper correction
does not update legacy CocoaPods trunk publications.

The failure-stack tests now run within the existing serialized capture suite.
Their assertions are unchanged; the change prevents independent test suites
from competing for the process-wide capture lock. It does not alter production
capture behavior or weaken the release gate.

After publication, upgrade with your app's package manager:

```sh
npm install @crumbsdk/react-native@0.0.1-rc.6 react-native-nitro-modules@0.37.1
npx --no-install crumb doctor
```

Rebuild the native app after upgrading and regenerate Expo native projects when
using prebuild. Preserve your current configuration and the bundled Podfile
helper or Expo plugin. Existing rc.5 users need no API migration. Earlier users
should also follow the [rc.5 migration](0.0.1-rc.5.md) and
[rc.4 bundled-native migration](0.0.1-rc.4.md).

Support floors remain React Native 0.79+, iOS 15.1+ for the adapter, Android
API 26+, Nitro 0.37.1, and Node.js 22+ for build commands. Expo requires a
development or production build; Expo Go is unsupported. Native Swift consumers
use SPM with the exact rc.6 tag (iOS 15+), and native Android consumers use the
exact Maven coordinates above (API 26+, Java 17 bytecode). CocoaPods trunk
publication is not required; rc.3 pods remain the legacy path.

## Publication after independent review

1. Merge the preparation PR after independent review and passing checks. Record
   the exact merge commit and verify version/tag checks on that commit.
2. Create the immutable native and adapter tags on that same commit. Wait for
   **Native SDK release** and verify its manifest revision, archives and
   SHA256SUMS.
3. Run **Publish native registries** with tag `0.0.1-rc.6`, target `maven`, and
   confirmation `publish 0.0.1-rc.6`. Wait for propagation and the clean consumer
   check. Do not select CocoaPods or `both`.
4. Run **Publish source-map CLI to npm** with tag `0.0.1-rc.6`, channel `next`,
   and confirmation `publish @crumbsdk/source-maps@0.0.1-rc.6`.
5. Run **Publish React Native SDK to npm** with tag
   `react-native-v0.0.1-rc.6`, channel `next`, and confirmation
   `publish @crumbsdk/react-native@0.0.1-rc.6`.
6. Verify exact versions, integrity, channel, bundled dependency resources and
   native pins. Confirm a fresh adapter installation exposes `crumb setup` and
   includes its pinned uploader. Do not promote npm `latest`.
7. Build fresh SPM, Maven, bare React Native and Expo consumers from the final
   published artifacts before updating installation availability claims.

Only the release coordinator performs these separately authorized manual actions
with existing workflows and credentials. Preparation checks do not publish.

## Validation and remaining acceptance

Version/contracts checks, native release checks and artifact verification, npm
quality/packaging checks and path-triggered examples must pass on the reviewed
candidate commit. A toolchain-specific local failure must be disclosed rather
than bypassed or reported as a pass.

Published-consumer, physical-device and hosted acceptance remain separate. In
particular, test the oldest supported React Native version, native Release
builds and real EAS Builds; exercise fatal JavaScript crash, relaunch,
exactly-once delivery and decoding to the original file/function/line on both
platforms. Verify raw stacks remain explicit when maps are absent or wrong.
An upload receipt alone is not proof of decoding. Export dry runs do not prove
on-device updates or rollback. Complete privacy, offline retry and customization
coverage and resolve critical/high-severity defects before pilot acceptance.

Keep reports, source maps, retained bundles, credentials and raw device evidence
private. Candidate publication does not imply these checks have passed.
